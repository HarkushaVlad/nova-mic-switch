# Collected third-party license texts

The release bundle includes actual license and notice text files collected from the installed Python distributions and Python runtime. The generated `THIRD-PARTY-NOTICES.md` and `manifest.json` in the bundle record their sources, versions, and SHA-256 hashes. A declaration in package metadata is not treated as a substitute for a license text.

Qt for Python 6.12.0 license files are curated verbatim under `packaging/licenses/qt-6.12.0/`; Qt Multimedia's FFmpeg 9.0.1 attribution JSON and eight license texts are curated under `packaging/licenses/ffmpeg-9.0.1/`. Both collections are checked against source URLs, versions, and SHA-256 values in their curation manifests. The collector fails if PySide6, PySide6_Essentials, PySide6_Addons, or shiboken6 is not version 6.12.0. Qt's attribution data identifies FFmpeg 9.0.1 as LGPL-2.1-or-later and says the Qt prebuilt binaries omit optional GPL or LGPLv3 components. These curated attribution files do not establish a full SBOM or a complete inventory of the final platform bundle; verify the exact artifact and build provenance before release.

Run `python scripts/collect_licenses.py` to collect into `build/licenses/`. The operation does not fetch files over the network by default. If the local Python installation does not include its license text, supply `--python-license PATH`, or explicitly run `--fetch-python-license` to retrieve the official CPython license for the active runtime version before packaging. The packaging spec uses a version/hash-matched precollection when available and otherwise collects locally without implicit network access.

Review the resulting attribution inventory for each exact release, including Qt runtime components and transitive dependencies. Collection does not establish legal compliance, satisfy any particular license obligation, or select a license for this project. It makes no HIDAPI license choice. No project-wide license is inferred here.
